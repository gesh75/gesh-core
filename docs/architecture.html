The shim pattern

A full-module alias. Because sys.modules is rebound, import db returns the gesh-core module itself — so attribute access, from-imports, underscore names, and test monkeypatching (monkeypatch.setattr(db, "DB_PATH", tmp)) all reach the one shared namespace.

# gesh-project-trading/db.py  — and the identical stub in gesh-project
import sys
from gesh_core import db as _impl
sys.modules[__name__] = _impl   # import db  →  the single gesh_core.db

The shared surfaces

Harmonization was decided per module — identical, engine-superset, product-canonical, or a union of both repos' best behavior. Never a blind overwrite. Phase 3 extracted 11; DCF, ledger, db_path, fetch, sentiment, and autopilot followed.

Database resolution · separate books by design

gesh-core can't use __file__ (it points inside the package), so DB paths resolve at call time. Each repo keeps its own gesh_financial.db (rule #44 — the engine and product paper books are deliberately separate); only the wash-sale tracker is wired cross-repo.

trading.state · db  GESH_DB_PATH → cwd/gesh_financial.db (path-only resolve; probe on connect; no /tmp)
tax_harvester     GESH_TRACKER_DB → GESH_TRADING_HOME → cwd (product wires → engine db)
allocation_config GESH_CONFIG_PATH → cwd/gesh_config.json (per-repo config)

Deliberately per-repo

Not everything should be shared. These stay local by design — they are engine-only, a deliberate policy difference, or genuinely different engines. Documented, not overlooked.
